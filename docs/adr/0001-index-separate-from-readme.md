# 0001 — 索引独立于 README,由程序生成到 SKILLS.md

## 状态

已接受

## 背景

工具需要一个"技能清单"来回答"我有哪些技能"。最初的构想是让程序在每次
添加技能时,把技能条目**追加进 `README.md`**。但 README 同时承担着
另一个职责:它是面向 GitHub 的开源项目文档,讲的是"这个工具怎么用",
内容由人手工编写、章节结构稳定。

两个职责同时压在一个文件上,产生了直接冲突:

1. **结构污染** — 程序追加的条目会插进 README 的章节之间,把手写的
   文档结构冲乱。每添加一个技能,README 就多一段,直到无法阅读。
2. **数据泄漏** — README 是要公开的。里面的技能清单会暴露使用者私人
   技能库的全部名称。这与"开源仓库不含任何私人技能内容"的目标直接矛盾。
3. **职责混淆** — README 是静态文档,技能清单是动态状态。把动态状态
   写进静态文档,意味着 README 每次加技能都要变脏,且无法用版本控制
   区分"文档改版"与"技能增删"。

## 决策

索引**不写入 README**。程序把索引生成为独立的 `SKILLS.md`,与 README
并存但职责分离:

- `README.md` — 手写,静态,讲工具怎么用。含一节**说明索引机制**,
  但不含索引内容本身。
- `SKILLS.md` — 程序生成,动态,列本机技能。**由算法自动维护**,
  添加/删除技能后自动重写。
- `SKILLS.md` **加入 `.gitignore`**,不进版本控制。仓库中放置
  `SKILLS.example.md`(假数据)演示格式。

## 后果

**正面**

- README 保持干净、可读、可公开。
- 索引可随仓库状态精确再生,不携带私人数据进公开仓库。
- 别的使用者在自己机器上跑,各自生成各自的 `SKILLS.md`,格式统一
  因而可互换阅读。这正是"索引表"的需求:每台机器自成索引。

**负面**

- 多了一个文件要理解。README 必须用一节解释这个分工,否则新使用者
  会困惑"为什么技能不在 README 里"。
- 索引与 README 存在轻微冗余:README 讲机制,SKILLS.md 是实例。

## 备选方案

- **全部写进 README** — 被否决:污染结构、泄漏数据、职责混淆,如上。
- **索引交给用户手工维护** — 被否决:必然与仓库状态脱节,失去"索引"
  的意义(索引的价值在于忠实反映状态)。
- **索引只存内存、不落盘** — 被否决:无法跨会话、无法分享、无法
  被别的工具消费。
